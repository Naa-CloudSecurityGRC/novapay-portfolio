# Gap Analysis & Recommendation: Quarterly SOX Evidence Collection

> **About this case:** NovaPay is fictional. The three interviews are simulated with role-played personas built from common control-owner experiences, to show the elicitation and synthesis method. The [interview guide](interview_guide.md) is ready for real interviews.

## 1. Who we spoke to

| Persona | Role | Controls owned | Evidence requests per quarter |
|---|---|---:|---:|
| P1 | Accounting Manager, Revenue | 9 | 22 |
| P2 | IT Operations Lead | 14 | 41 |
| P3 | Treasury Analyst | 5 | 12 |

## 2. What we heard

| Theme | Evidence from interviews | Tag |
|---|---|---|
| Unclear evidence expectations | "I never know if a screenshot is enough until it comes back." (P2) · 2 of 3 had a request returned last quarter | Process |
| Requests arrive in bursts | All three receive most requests in the 2 weeks after quarter end, during close | Process |
| Same evidence asked twice | Internal audit and external auditors request the same report separately (P1, P3) | Process |
| Evidence lives in many places | Email, shared drives, ticketing tool; no single place to submit (P2) | Technology |
| Report reliability questions | P1 rebuilds the same system report each quarter because parameters must be shown (IPE) | Data |

## 3. Gap analysis

| Area | Current state | Desired state | Gap | Priority |
|---|---|---|---|---|
| Evidence standards | Requirements explained in each email request | A written "evidence card" per control: what, from where, format, example | No documented standard | High |
| Timing | ~80% of requests in the first 2 weeks after quarter end | Requests spread through the quarter; interim testing where possible | No testing calendar shared with owners | High |
| Duplicate requests | Internal and external audit ask separately | One request, one upload, shared with both (reliance) | No coordinated request list | Medium |
| Submission channel | Email and shared drives | One portal (GRC tool or Jira) with status tracking | No single channel | Medium |
| Report evidence (IPE) | Rebuilt manually each quarter | Saved report parameters with system-generated run log | No standard IPE approach | Medium |

## 4. Recommendation (one page)

**Recommendation:** run a 90-day pilot of standardized evidence requests for the 28 controls owned by these three teams.

1. **Evidence cards (weeks 1-4):** one-page card per control with a sample of acceptable evidence; reviewed with each owner.
2. **Shared testing calendar (week 2):** publish due dates for the full year; move 30% of testing to interim periods.
3. **Single request list with external audit (weeks 3-6):** agree which evidence they will rely on; one upload serves both.
4. **Jira as the submission channel (weeks 4-8):** one ticket per request, with status, due date and attachments.
5. **Saved IPE reports (weeks 6-10):** saved parameters plus a run log for the 5 most-used reports.

**Expected impact (to confirm in the pilot):** fewer returned requests, fewer duplicate asks, and less evidence work during close.

**Success measures:** returned-request rate · average days from request to accepted evidence · control owner survey score (1-5).
